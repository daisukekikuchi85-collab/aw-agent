# セットアップ — 初期設定ウィザード

導入直後のユーザー（多くは非エンジニア）と対話しながら、チームを本人仕様にする。

## 大前提

- **相手はターミナルに不慣れである**という前提で話す。専門用語には必ず一言の注釈を付ける
- 一度に複数のことを聞かない。**1つ質問して、答えを待ってから次へ進む**
- 途中でやめても壊れない。「ここまでで一旦終わりますか？」といつでも聞いてよい
- ファイルを書き換える前に、何をどう変えるかを一言伝える

## 手順

### 0. 状況を確認する

`knowledge/about-us.md` の「名前:」が空欄なら**初回セットアップ**。
埋まっていれば**再設定**なので、「何を変えますか？（呼び方 / プロフィール / メンバーの追加削除）」と聞く。

### 1. あいさつ

次のことを短く伝える。長く話さない。

- これから5分ほどで初期設定をすること
- 設定するのは「あなたのこと」と「メンバーの呼び方」の2つだけであること
- 途中でやめても、後から `/setup` でいつでも再開できること

### 2. オーナーのことを聞く

以下を**1つずつ**聞き、`knowledge/about-us.md` を Edit ツールで更新する。

1. お名前（チーム内で何と呼べばよいか）
2. 所属・役割
3. 主にどんな仕事をしているか（1〜2行でよい）
4. いま力を入れていること（あれば。無ければ飛ばす）

答えを聞いたら `CLAUDE.md` の「このチームについて」の下に、
1〜2行で「オーナーは〇〇を担当している」と書き足す。

### 3. メンバーの呼び方を決める

まず現在の13人を役割つきで一覧提示する（`knowledge/agent-nicknames.md` の表をそのまま見せる）。
そのうえで、次の3つから選んでもらう。

- **A案: このままでよい** — 何もしない。手順5へ
- **B案: 何人か名前を変えたい** — 変えたい人だけ聞いて変更する
- **C案: 使う人だけ残したい** — 使うメンバーを選んでもらい、残りを削除する

**C案を選ばれたとき**は、削除の前に必ず確認する。

- 「削除すると `.claude/agents/` からファイルが消えます。後から戻すには
  ダウンロードした ZIP から該当ファイルをコピーし直す必要があります。進めますか？」
- **統括役 `rosa` は削除させない**（振り分けができなくなるため）。
  希望されたら理由を説明して残すよう勧める
- 削除したメンバーの行は `CLAUDE.md` のメンバー表と
  `knowledge/agent-nicknames.md` の一覧からも消す

### 4. 名前を書き換える

呼び方を変えるときは、変更する名前ごとに次の3か所を Edit ツールで書き換える。

1. `.claude/agents/<ファイル名>.md` の frontmatter の `description:` — 旧ニックネームを新しい名前に置換
2. 同じファイルの本文中に出てくる旧ニックネーム
3. `CLAUDE.md` のメンバー表と `knowledge/agent-nicknames.md` の一覧表

**絶対に変えてはいけないもの**（変えると動かなくなる）:

- frontmatter の `name:` の値（`rosa` `sales` などの英字）
- `.claude/agents/` のファイル名
- 表の左端「ファイル名」列の値

書き換えたら、変更した箇所を「〇〇さん → △△さん に変更しました」と1行ずつ報告する。

### 5. 動作確認

「では動くか試してみましょう」と伝えて、統括役を実際に呼び出す。

例: 「（統括役の名前）、自己紹介して。あわせてチームに誰がいるか教えて」

Task ツールで統括役のエージェントを起動し、応答が返ることを確認する。
返らなければ `docs/FAQ.md` を見るよう案内する。

### 6. 締めくくり

次の3点だけを短く伝えて終わる。

- 使い方の詳しい説明は、ダウンロードしたフォルダの `docs/GUIDE.md` にあること
- 呼び方はあとから `/setup` でいつでも変えられること
- 仕事の前提（社内用語・よく関わる相手など）を `knowledge/about-us.md` に
  書き足すほど、指示が短くて済むようになること

最後に `knowledge/about-us.md` の「名前:」が埋まっていることを確認する
（次回このスキルが初回か再設定かを判断する目印になる）。

## やってはいけないこと

- ユーザーに聞かずにファイルを書き換える
- 一度に4つも5つも質問する
- `name:` やファイル名を変更する
- `rosa` を削除する
- エラーが出たときに黙って別の方法を試す（何が起きたかを伝えてから次の手を提案する）
